# Captured Android installation attribution

The APK 4.26.5 has separate shared-page click, installation, and Play referrer
operations. The SDK accepts their observed provenance explicitly and saves it
in `WebmasterRegistrationSession.AndroidAttribution`. A completed report is
installation attribution evidence; it does not confirm Webmaster counts or
rewards.

`NewAndroidGuestProfile` generates a virtual device identity. It does not create
an actual Play installation or its referrer. Its native `af_media_source` cache
starts as `Undefined` when that field exists in the template. Capture records
must retain the actual installation's profile/CUID and cannot be attached to a
new random profile.

## Inputs and requests

`AndroidAttributionCapture` contains `device_id`, optional `click`, optional
`install`, and optional `install_referrer`. `SetAndroidAttributionCapture`
validates and copies those inputs without network activity. No share owner,
share ID, or shared URL is converted into an install referrer, invite code, or
ReportUser `bind_uid`.

| Method | Actual contract | Input provenance |
| --- | --- | --- |
| `ReportAndroidShareClick` | POST `/api/srn/ck`, captured common query plus form body | Public share-page app-open event |
| `ReportAndroidInstall` | POST `/api/srn/ins`, endpoint query parameters, empty body | Android package/install and first-launch state |
| `QueryAndroidInstallReferrer` | POST `/api/srn/ref`, same query plus optional `referer_data`, empty body | Actual Play `getInstallReferrer()` value or unavailable callback |

The click form contains the verified constants `pid=tera_sharelink` and
`pdetail=header_button`, plus captured `c` (the full `page_url`), `tera_link_id`,
`tera_link_type`, `lang`, `os_version`, `device`, `af_dp` (`deep_link`),
`referrer`, and nullable `agency`/`op_source`. The browser UA and optional
browser cookies are captured separately from the native profile. Its Referer
header excludes the URL fragment while `c` preserves actual `location.href`.

The required click `common_params` map preserves the actual interceptor query:
`app_id`, `web`, `channel`, `clienttype`, `jsToken`, `dp-logid`, `version`,
`devuid`, `cuid`, `lang`. Browser mode (`clienttype=5`) retains the page's
`app_id=250528`, `web=1`, `channel=dubox`, and zero version/device IDs; its
actual `jsToken` and `dp-logid` are not generated by the native SDK. WebView
mode (`clienttype=1`) retains the captured same-installation CUID and native
query, plus `bridge_body` final form fields `version`, `devuid`, and `cuid`.
The final endpoint form's browser language wins the bridge's default language;
the common query's native language can differ. `browser_cookies` contains only
the observed share-page browser cookie header. Native account cookies are
never substituted for this header.

The install query fields are `clipboard` (the APK sends an empty string),
`device_country`, `device_lang`, `os_version`, `device`, `install_time`, and
`first_launch_time`. `install_time` is nullable when package information was
unavailable; otherwise it is `PackageInfo.firstInstallTime` in milliseconds.
`first_launch_time` is the actual saved Unix-second value multiplied by 1000.
Missing observations are not replaced with the time of account creation.
`is_first_launch` is explicit local state and is not an HTTP parameter.

An absent/null `install_referrer` omits `referer_data`, matching the native
unavailable/timeout query. An actual empty Play string sends `referer_data=`.
The exact observed string is URL-encoded once; it is never reconstructed from
the referral share metadata.

## Returned and restored state

Each report preserves `attempted`, `succeeded`, `http_status`, `errno`,
`request_id`, and the exact valid JSON `raw_response`. `/ref` succeeds only
with an explicit zero errno and nonnull object `data`. Its nullable
`mediaSource`, `status`, `agency`, `campaign`, `code`, `adSet`, `opSource`,
`deepLinkValue`, and `deeplink` are preserved; additional response fields remain
in the raw JSON. The response's attribution `status` is not interpreted as an
API success code.

On an explicit first launch, the confirmed response supplies
`app_install_media_source` and both native/legacy `af_media_source` query maps.
The APK's null/blank media-source cache transformation uses the literal string
`null`; the original nullable server field remains intact. A valid returned
deeplink `uk` is saved as local `tera_link_webmaster_uk`. It is not assigned to
the account UID, ReportUser, or invite report. Later-launch results are saved
without replacing the installation's original media cache.

`RestoreAndroidAttribution` imports already observed reports on a fresh client
with the same installation identity. A claimed success requires the actual
HTTP 200 response, explicit errno zero, and matching raw metadata. It derives
missing referrer/cache fields from that response and updates a copied profile
without HTTP. Unknown or failed attempts remain attempted and block automatic
replay. Successful reports return their saved outcome without another request.
Regular session restore requires a complete, internally consistent saved
state; it cannot overwrite a client that already has attribution state.

Captures, browser cookies, tracking URLs, and raw responses may contain private
tokens. Store them with the same permissions as session files and do not print
them to normal logs. Capture/report APIs make no calls unless explicitly
invoked; setting or importing provenance does not create an account.

## Source evidence

The contracts come from the supplied APK SHA-256
`73340b723c45cca9bb44289b1ca3ea2e5e207f4af406a6970bb2ef1badf7f696`:
`ITeraLinkApi` Retrofit annotations, native `aw.q`/`aw.b` first-launch/cache
consumers, and the public shared-page modules `1f03`, `35d0`, and `7404`.
Click wire replay executes those actual bundled functions offline. This does
not establish the service's Webmaster credit eligibility rules.
